
# Azure_MSSQL_Server_with_Private_Endpoint

    This Project is a Terraform project that provisions a secure, production-ready Azure MSSQL Database Server connected to a Linux Virtual Machine through a fully private network
    The SQL Server is never exposed to the public internet all database traffic flows exclusively within the Azure Virtual Network via a Private Endpoint backed by a Private DNS Zone.

## Key highlights:

    Azure Virtual Network with two dedicated subnets (vm-subnet & pe-subnet)
    Ubuntu Linux VM (Standard_D2s_v3) with RSA 4096-bit SSH key authentication
    NSG allowing only SSH (port 22) inbound traffic to the VM
    Azure MSSQL Server + Database with zero public internet exposure
    Private Endpoint + Private DNS Zone for seamless internal SQL name resolution
    Remote Terraform state stored in Azure Blob Storage

## Resource Explanation

    Networking

    Virtual Network (10.0.0.0/16) — the main network container for all resources
    vm-subnet (10.0.1.0/24) — hosts the Ubuntu VM's NIC
    pe-subnet (10.0.2.0/24) — hosts the Private Endpoint for the SQL Server
    Public IP — static IP assigned to the VM for SSH access only
    NSG — allows inbound TCP on port 22 (SSH); blocks everything else

    Virtual Machine
    
    Ubuntu Server 22.04 LTS on Standard_D2s_v3
    RSA 4096-bit SSH key pair generated by Terraform; private key saved as vm-private-key.pem
    OS disk: 80 GB Standard LRS, auto-deleted on VM termination
    Connected to vm-subnet with the static Public IP attached

    MSSQL Server & Database
    
    Azure MSSQL Server (version 12.0) with admin credentials
    A Basic SKU database created on the server
    No public network access — the server is reachable only via the Private Endpoint

    Private Endpoint & DNS
    
    Private Endpoint deployed in pe-subnet, pointing to the MSSQL Server
    Private DNS Zone (privatelink.database.windows.net) linked to the VNet
    DNS A Record maps the SQL Server hostname to its private IP 
    so the VM can resolve and connect using the standard FQDN without any public routing

## Configuration — terraform.tfvars

    service_principal = {
      client_id       = "<CLIENT_ID>"
      client_secret   = "<CLIENT_SECRET>"
      tenant_id       = "<TENANT_ID>"
      subscription_id = "<SUBSCRIPTION_ID>"
    }
    
    rg_details = {
      name     = "<RESOURCE_GROUP_NAME>"
      location = "<AZURE_REGION>"           # e.g., "australiaeast"
    }
    
    vnet_details = {
      name          = "vnet"
      address_space = "10.0.0.0/16"
    }
    
    vm_details = {
      name    = "sql-demo-ubuntu-vm"
      vm_size = "Standard_D2s_v3"
      os_profile = {
        computer_name  = "hostname"
        admin_username = "<VM_USERNAME>"
        admin_password = "<VM_PASSWORD>"
        ...
      }
      ...
    }
    
    mssql_details = {
      name                         = "<UNIQUE_SQL_SERVER_NAME>"
      version                      = "12.0"
      administrator_login          = "<SQL_USERNAME>"
      administrator_login_password = "<SQL_PASSWORD>"
    }

## Deployment

    # Step 1: Initialize Terraform (downloads providers, connects backend)
    terraform init
    
    # Step 2: Validate configuration
    terraform validate
    
    # Step 3: Preview changes
    terraform plan -var-file="terraform.tfvars"
    
    # Step 4: Apply and provision
    terraform apply -var-file="terraform.tfvars"

## Outputs

    After a successful apply, Terraform will display:

    Output                               Description
    
    vm_public_ip             Public IP of the Ubuntu VM for SSH access
    sql_private_ip           Private IP of the SQL Server via Private Endpoint
    sql_server_fqdn          Fully Qualified Domain Name of the MSSQL Server
    ssh_command              Ready-to-use SSH command to connect to the VM

### Connect to VM via SSH

    ssh -i vm-private-key.pem azureuser@<vm_public_ip>

### Connect to SQL Server from inside the VM

    # Install sqlcmd or use any SQL client
    sqlcmd -S <sql_server_fqdn> -U <admin_username> -P <admin_password>

## Destroy Infrastructure

    terraform destroy -var-file="terraform.tfvars"

    This will permanently delete all provisioned resources 
    including the VM, MSSQL Server, VNet, and Private Endpoint.
